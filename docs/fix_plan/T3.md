# T3 — Натив Android: шаги, батарея, уведомления

**Файлы (только эти):**
`android/app/src/main/kotlin/uz/ecokomitet/eco_mobile/MainActivity.kt`,
`android/app/src/main/java/uz/ecokomitet/eco_mobile/*.java`,
`android/app/src/main/res/**` (новые drawable),
`lib/steps/steps_service.dart`, `lib/notifications/notification_service.dart`.
`lib/state/store.dart` НЕ трогать (им занята другая сессия).

## 1. Сенсор-листенер молотит JSON на main thread

`MainActivity.kt`, live-путь шагов: `sm.registerListener(listener, sensor,
SENSOR_DELAY_NORMAL)` регистрируется без Handler — колбэки приходят на main
thread, и внутри каждый (с дебаунсом 1 с) делает `StepSamples.add()` (полный
парсинг JSON-массива из SharedPreferences + полная перезапись) и
`StepSamples.todaySteps()` (второй полный парсинг). Массив хранится 8 дней без
ограничения количества — час ходьбы в день ≈ десятки тысяч записей, сотни КБ
JSON дважды в секунду на UI-потоке. Это jank и риск ANR.

- Зарегистрировать listener с Handler фонового HandlerThread; результат в
  EventSink постить через runOnUiThread (он уже есть в коде).
- Прореживать чекпоинты: персистить не чаще 1 записи в 30–60 с; текущее
  сегодняшнее число для UI считать в памяти (последний persisted todaySteps +
  дельта сырого счётчика) без полного парсинга.
- `Executors.newSingleThreadExecutor()` в getTodaySteps создаётся на каждый
  вызов — вынести в поле класса.

## 2. Повторный requestPermission подвешивает Dart-future навсегда

`MainActivity.kt`: `pendingPermissionResult = result` перезаписывает предыдущий
Result без ответа — если Dart вызвал 'requestPermission' второй раз, пока открыт
системный диалог, первый Future никогда не завершится, `await` в store висит
до перезапуска.

- Перед перезаписью отвечать старому: если `pendingPermissionResult != null`,
  новому вызову сразу вернуть текущее состояние (`hasActivityPermission()`), не
  трогая pending; либо ответить старому и заменить.
- Страховка в `lib/steps/steps_service.dart`: `.timeout(Duration(seconds: 90),
  onTimeout: () => false)` на invokeMethod('requestPermission').

## 3. Worker впустую жрёт батарею без разрешения

`StepSampleWorker.doWork()` безусловно зовёт `StepSamples.readCounter(ctx, 5000)`.
Без ACTIVITY_RECOGNITION (API 29+) сенсор молча не отдаёт события — latch ждёт
полные 5 секунд. Worker перепланируется вечно, даже если разрешение так и не дали.

- В начале doWork(): проверка `checkSelfPermission(ACTIVITY_RECOGNITION)` (SDK
  >= 29) и наличия сенсора → при отказе `return Result.success()` сразу.

## 4. Иконка уведомлений — цветной launcher вместо монохрома

`StepNotifier.java`: `setSmallIcon(ctx.getApplicationInfo().icon)` и
`notification_service.dart`: `AndroidInitializationSettings('@mipmap/ic_launcher')`.
Small icon рендерится по альфа-каналу → в статус-баре серый квадрат.

- Добавить монохромный `res/drawable/ic_stat_eco.xml` (белый силуэт листа/логотипа
  на прозрачном, vector drawable) и использовать в обоих местах:
  `setSmallIcon(R.drawable.ic_stat_eco)` и `AndroidInitializationSettings('ic_stat_eco')`.

## 5. Мост для бэкфилла прошлых дней (только натив-часть)

Натив хранит 8 дней сэмплов, но наружу выставлен только 'getTodaySteps'.

- Обобщить `StepSamples.todaySteps()` до `stepsForRange(from, to)` и добавить
  MethodChannel-метод `'getStepsForDay'` (аргумент — epoch millis начала дня).
- В `steps_service.dart` добавить обёртку `Future<int?> stepsForDay(DateTime day)`.
- Вызов из store подключит другая сессия (волна 3) — store.dart не трогать.

## 6. Мелочи

- `StepNotifier.java`: фолбэк `name = "Activity"` для канала — заменить на
  нейтральный или не создавать канал при пустом имени (как уже сделано для title).
- `NotificationService.init(store)`: перед `store.addListener(...)` снять
  прежний listener (`_store?.removeListener(_onStoreChanged)`), чтобы повторный
  init (Retry-сценарий main.dart) не плодил подписки.
