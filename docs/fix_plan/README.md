# План фиксов по итогам аудита (2026-07-02)

Источник: полный аудит (96 находок, ключевые подтверждены верификаторами).
Исключено по решению: защита бэкенда от расходов (auth, rate limit, квоты).

## Как работать

- Каждая задача — отдельная вкладка/сессия. Промпт для сессии: «Выполни задачу
  из docs/fix_plan/T<N>.md. Работай ТОЛЬКО с файлами из списка задачи.»
- Файлы задач внутри одной волны не пересекаются — волну можно запускать
  параллельно в одном рабочем дереве.
- В конце задачи сессия делает `flutter analyze` и коммитит ТОЛЬКО свои файлы:
  `git add <файлы задачи> && git commit`.
- Волна 2 запускается после того, как ВСЯ волна 1 закоммичена (задачи волны 2
  используют ключи локализации из T4 и логику store из T1).
- T2 (база продуктов) — самая долгая, может продолжаться параллельно с волной 2:
  её файлы (assets/, tooling/) никто больше не трогает.

## Волна 3 — опционально, позже

- Доступность: Semantics для кастомных тумблеров/кнопок, тач-таргеты (сквозной проход).
- Беременность/лактация в LifeStage (продуктовое решение + вопрос в профиле).
- Разрезание `AppStore` на доменные сторы и `ui.dart` на модули (рефакторинг, делать в одиночку, не параллельно ни с чем).
- Бэкфилл шагов из натива: Dart-вызов `getStepsForDay` из `syncSteps()` (натив-часть делает T3).
- Серверный таймаут fetch к DeepSeek (`AbortSignal.timeout`) — functions/index.js.
