# T1 — Логика store и формулы энергии

**Файлы (только эти):** `lib/state/store.dart`, `lib/nutrition/energy.dart`

Номера строк ориентировочные — недавно был merge, ищи по именам методов.

## 1. КРИТИЧНО: убрать фабрикацию данных пользователя

В `AppStore.init()` методы `_seedRandomWaterMonth()` и `_seedRandomStepsMonth()`
вызываются БЕЗУСЛОВНО у всех пользователей при каждом запуске (в отличие от еды,
которая под флагом `_seedDemoFood = bool.fromEnvironment('SEED_DEMO_FOOD')`).
Они записывают случайные 2500–13500 шагов и 600–2399 мл воды в каждый пустой
день последних 30 дней прямо в Hive, в те же ключи, что и реальные данные.

- Загейтить оба вызова: `if (_seedDemoFood) { _seedRandomStepsMonth(); _seedRandomWaterMonth(); }`.
- В `_seedRandomStepsMonth` убрать подмену живого счётчика:
  `if (steps <= 0) steps = stepsHistory[ymd()] ?? steps;` — удалить.
- В `syncSteps()` ослабить guard `if (n != null && n > 0 && n != steps)`:
  принимать и реальный `0` от натива (комментарий «чтобы не затирать демо-данные»
  больше не актуален). Условие: `n != null && n != steps`.
- Пустые графики — это честно; никаких placeholder-данных не сеять.

## 2. Кламп калорий не должен превращать «похудеть» в профицит

`calorieGoal()` в `lib/nutrition/energy.dart`: клэмп до `minimumCalorieGoal(sex)`
(1500/1200) не зависит от возраста и применяется безусловно. Пример: мальчик
6 лет, 20 кг — TDEE ≈ 1139, цель 'lose' → клэмп поднимает до 1500 (профицит!).
Та же проблема у миниатюрных пожилых женщин (TDEE 1179 → цель 1200).

- Пол снизу не должен превышать TDEE: `final effectiveFloor = min(floor, tdee);`.
- Для `ageYears < 18` не применять взрослые 1500/1200 — использовать долю от
  TDEE (например, floor = 0.85 × tdee для 'lose', не ниже BMR) — задокументируй
  выбранное правило в doc-комментарии.
- Прокинь `ageYears` в `calorieGoal`/`minimumCalorieGoal`, где нужно
  (`calorieGoalFor` уже имеет возраст). Проверь все call-sites
  (`grep -rn "calorieGoal\|minimumCalorieGoal" lib/`).

## 3. Полуночный сброс шагов (у воды сделан, у шагов — нет)

Для воды есть `waterDate`-ролловер в `init()` и `rolloverWaterIfNeeded()`
(вызывается из main.dart onResume). Для шагов аналога нет: утром отображается
вчерашнее значение, а guard в syncSteps не пускает свежий 0.

- Хранить `stepsDate` (аналогично `waterDate`); в `init()` и в ролловер-методе
  при смене дня: записать вчерашний итог в `stepsHistory[вчера]`, `steps = 0`.
- Ролловер шагов дёргать там же, где `rolloverWaterIfNeeded()` — найди вызов и
  добавь рядом (метод в store, вызов уже есть в main.dart — main.dart НЕ трогать,
  поэтому объедини: пусть `rolloverWaterIfNeeded()` станет `rolloverDayIfNeeded()`
  с обратной совместимостью, либо вызывай шаговый ролловер изнутри водного).

## 4. Вода: убрать жёсткий кламп по цели

`stepWater()` и `stepWaterForOffset()`: `.clamp(0, waterGoal)` — пользователь
физически не может записать больше цели (выпил 2600 при цели 2000 — данные
искажаются). UI уже умеет рисовать >100% (`minTop: waterGoal * 1.3` в health).

- Заменить верхнюю границу на разумный потолок: `.clamp(0, 6000)`.

## 5. Норма воды: пересчёт при изменении веса/профиля

`waterGoal = waterGoalFor(...)` сейчас пересчитывается только в `init()` и
`completeOnboarding()`. Комментарий в init() обещает актуальность при изменении
веса — это неправда до перезапуска.

- Вынести пересчёт в приватный `_refreshWaterGoal()` (с гвардом полноты профиля,
  как в init()) и вызывать из `saveBodyMetrics()`, `setWeight()`,
  `updateProfileBasics()` перед `_persist()`/notifyListeners.

## 6. Устойчивость хранилища

- `LogItem.fromMap` (и `BodyMetricEntry.fromMap`, если есть): мягкие касты с
  дефолтами (`m['name'] as String? ?? ''`, `(m['kcal'] as num?)?.toInt() ?? 0`).
  При загрузке дневника оборачивать каждый элемент в try/catch и пропускать
  битые записи (с debugPrint), а не ронять весь init().
- `Hive.openBox(_boxName)` в init(): try/catch → при ошибке
  `Hive.deleteBoxFromDisk(_boxName)` → повторный openBox (лог об этом). Иначе
  битый box = вечный кирпич на старте (Retry перечитывает тот же файл).
- ВАЖНО: merge коллеги добавил в `LogItem` поле `pieces` — не сломай его
  сериализацию (`toMap`/`fromMap`).
